# Testing Strategy
Level: 3 (Application)
Scope: Governance
Category: Testing & Quality
Purpose: Test strategy, quality levels, and conventions for the Python FastAPI migration project. Adapted from original Angular testing guardrails and Python best practices.

> Test strategy, quality levels, and conventions for this project.
> Updated by `@discovery-knowledge` as new documentation is analyzed.

## Philosophy

**Test Pyramid** (preferred distribution):
- 70% **Unit tests** — fast, isolated, test business logic in services
- 20% **Integration tests** — route + service + mocked httpx calls (using respx)
- 10% **End-to-end tests** — optional; full application flow with test middleware (future)

**Principles**:
- Tests must be **deterministic** — same input always produces same output
- Tests must be **fast** — unit tests run in milliseconds, integration tests in seconds
- Tests must be **isolated** — no shared state between tests; use fixtures
- Tests must **verify behavior** — not implementation details (avoid over-mocking)

## Test Levels

| Level | Scope | Tooling | Coverage target |
|---|---|---|---|
| **Unit** | Single function/class in isolation; mock external dependencies | pytest, unittest.mock | ≥ 80% |
| **Integration** | Route → service → httpx call (mocked with respx) | pytest, respx, TestClient | ≥ 70% |
| **End-to-End** | Full application flow (optional) | pytest + live test middleware | N/A (manual validation) |

## Mocking Conventions

### What to mock

- **Injected dependencies**: httpx.Client, external services, time provider
- **External I/O**: File system, network calls, database (if added)

### What NOT to mock

- **Static utility helpers**: Pure functions with no side effects (e.g., `validate_dni()`, `format_date()`)
  - **Rationale**: Mocking pure functions adds noise without value; call them directly
- **Pydantic models**: Data validation is part of the logic being tested
- **Python standard library** (e.g., `datetime`, `json`): Use real implementations; mock only when testing time-dependent behavior (via TimeProvider)

### Mocking patterns

**Good mocking** (external HTTP call):
```python
import pytest
from unittest.mock import Mock

def test_submit_query_success():
    # Mock httpx.Client
    mock_http_client = Mock()
    mock_response = Mock()
    mock_response.status_code = 200
    mock_response.json.return_value = {"id": "123", "status": "success"}
    mock_http_client.post.return_value = mock_response
    
    service = QueryService(http_client=mock_http_client, config=mock_config)
    result = service.submit_query(valid_request)
    
    assert result.status == "success"
```

**Bad mocking** (static helper):
```python
# ❌ AVOID: Mocking a pure function
def test_submit_query(mocker):
    mocker.patch("app.utils.validators.validate_dni", return_value=True)
    # This is noise — just call validate_dni() directly!
```

## Fixture Conventions

**Rule**: One fixture module per entity or endpoint.

**Structure**:
```
tests/
  fixtures/
    query_fixtures.py        # QueryRequest, QueryResponse
    config_fixtures.py       # AppConfig instances
    time_fixtures.py         # FakeTimeProvider
    http_fixtures.py         # respx mocks
```

**Fixture naming**:
- Use descriptive names: `valid_query_request`, `error_query_response`, `timeout_http_client`
- Avoid generic names: `data`, `obj`, `test_object`

**Example fixture** (`tests/fixtures/query_fixtures.py`):
```python
import pytest
from app.models.query import QueryRequest, QueryResponse

@pytest.fixture
def valid_query_request():
    return QueryRequest(
        operationType="consulta_cuentas",
        parameters={"dni": "12345678A"},
        timestamp="2026-05-08T12:00:00Z"
    )

@pytest.fixture
def success_query_response():
    return QueryResponse(
        id="req-uuid-1234",
        status="success",
        data=[
            {"id": "CTA-001", "estado": "active"},
            {"id": "CTA-002", "estado": "pending"}
        ],
        metadata={"processingTimeMs": 150}
    )

@pytest.fixture
def error_query_response():
    return QueryResponse(
        id="req-uuid-1234",
        status="error",
        errors=[
            {
                "code": "ERROR_VAL_MISSING_DNI",
                "message": "DNI is required",
                "field": "dni"
            }
        ]
    )
```

## Test Naming Conventions

| Element | Convention | Example |
|---|---|---|
| **Test file** | `test_<module>.py` | `test_query_service.py`, `test_query_routes.py` |
| **Test class** | `Test<ClassName>` (optional) | `TestQueryService`, `TestQueryRoutes` |
| **Test function** | `test_<action>_<condition>_<expected>` | `test_submit_query_with_valid_dni_returns_success()` |
| **Fixture function** | `<descriptive_name>` | `valid_query_request`, `timeout_http_client` |

**Test naming pattern**:
```python
# Pattern: test_<method>_<condition>_<expected_result>
def test_submit_query_with_valid_dni_returns_success():
    pass

def test_submit_query_with_invalid_dni_raises_validation_error():
    pass

def test_submit_query_with_middleware_timeout_raises_timeout_error():
    pass
```

## Error Branch Test Requirements

**Every error branch MUST verify all three of the following**:

1. **Exception is thrown** — assert it is of the expected type
2. **Error-registration call occurred** — verify the project's error service received the correct arguments (if applicable to this project)
3. **Exact error code** — capture the exception argument and verify the error code constant matches

> ⚠️ **A test that only verifies the error-registration call without asserting the exception is thrown is INCOMPLETE** — it cannot detect swallowed exceptions.

**Example**:
```python
def test_submit_query_missing_dni_raises_error():
    invalid_request = QueryRequest(operationType="consulta_cuentas", parameters={})
    service = QueryService(...)
    
    # 1. Assert exception is thrown
    with pytest.raises(ValidationError) as exc_info:
        service.submit_query(invalid_request)
    
    # 3. Assert exact error code
    assert exc_info.value.code == "ERROR_VAL_MISSING_DNI"
    assert "dni" in exc_info.value.message.lower()
```

## Test Environment Activation

⚠️ **Mandatory**: All integration tests must explicitly activate the test configuration.

**Test configuration file**: `tests/.env.test`

**Rule**: Without explicit test config activation, the application will attempt to load production config, and HTTP calls will target real URLs (causing test failures or unintended side effects).

**Activation mechanism** (`tests/conftest.py`):
```python
import pytest
import os

@pytest.fixture(scope="session", autouse=True)
def load_test_config():
    """
    Force test environment activation.
    Sets ENV=test and reloads config from tests/.env.test.
    """
    os.environ["ENV"] = "test"
    # Reload AppConfig with test environment
    from app.config import settings
    settings.reload()  # Or equivalent reload mechanism
    yield
    # Cleanup after tests
    del os.environ["ENV"]
```

**Test configuration file template** (`tests/.env.test`):
```ini
ENV=test
API_BASE_URL=http://mock-middleware.test/api
DEFAULT_LANG=es-ES
SUPPORTED_LANGS=es-ES,en-EN
REQUEST_TIMEOUT_MS=5000
```

| Gate | Requirement | Blocks |
|---|---|---|
| **All unit tests pass** | 100% pass rate | PR merge |
| **Coverage threshold met** | ≥ 80% overall | PR merge |

## Test Types by Layer

### Unit Tests (services/)

**Scope**: Test service methods in isolation; mock all external dependencies.

**Example**:
```python
# tests/services/test_query_service.py
def test_submit_query_success(valid_query_request, mock_http_client, mock_config):
    service = QueryService(http_client=mock_http_client, config=mock_config)
    result = service.submit_query(valid_query_request)
    assert result.status == "success"
```

### Integration Tests (routes/)

**Scope**: Test FastAPI route → service → httpx (mocked with respx).

**Example**:
```python
# tests/integration/test_query_endpoint.py
import respx
from fastapi.testclient import TestClient

@respx.mock
def test_query_endpoint_success(client, valid_query_request):
    # Mock middleware response
    respx.post("http://mock-middleware.test/api/query").mock(
        return_value=httpx.Response(200, json={"id": "123", "status": "success"})
    )
    
    response = client.post("/api/query", json=valid_query_request.dict())
    assert response.status_code == 200
    assert response.json()["status"] == "success"
```

### Template Rendering Tests (templates/)

**Scope**: Test Jinja2 templates render correctly with given context.

**Example**:
```python
# tests/templates/test_template_rendering.py
from jinja2 import Environment, FileSystemLoader

def test_consulta_cuentas_template_renders_accounts():
    env = Environment(loader=FileSystemLoader("app/templates"))
    template = env.get_template("consulta-cuentas.html")
    
    context = {
        "accounts": [{"id": "CTA-001", "estado": "active"}],
        "dni": "12345678A"
    }
    
    rendered = template.render(context)
    assert "CTA-001" in rendered
    assert "active" in rendered
```

## Parametrized Tests

**Use `@pytest.mark.parametrize` for testing multiple inputs**:

```python
@pytest.mark.parametrize("dni,expected_valid", [
    ("12345678A", True),
    ("12345678Z", True),
    ("1234567A", False),   # Too short
    ("123456789A", False), # Too long
    ("12345678a", False),  # Lowercase letter
])
def test_validate_dni(dni, expected_valid):
    result = validate_dni(dni)
    assert result == expected_valid
```
